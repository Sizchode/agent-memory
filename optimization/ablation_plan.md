为唯一主对照，识别必要、有害和冗余模块，再决定是否简化，以及是否需要关键交互消融。

目标是根据消融保留必要机制、删除冗余逻辑，并明确适用范围，不是反复挑选最方便解释的结果。

## 第一阶段

这里统计的是六组可消融机制，不是六个全部人工设计选择。建图侧三组、检索/读出侧三组；
支持投影和下列模块内部选择仍需披露，不把它们隐去后声称只有三个建图 heuristic。

| 所属部分 | 现有具体选择（不是新增方法） | 当前证据范围 |
|---|---|---|
| 关系归一 | 每关系前两个不同三元组作例子；embedding 分组后联合判断；同 canonical 再合并；最小输入 id 的 canonical 作代表 | 当前消融仅取消最终 canonical 键的应用，未逐项检验这条生成链 |
| 来源选择 | 主体/关系分槽；按 loader 来源位置取最新；末来源多值全留；所有内容关系使用同一规则 | latest 消融只改变图，旧 reader 附录不变 |
| discourse | 使用来源 schema 的角色分类过滤支持 | 单项只取消图过滤，未取消附录中的过滤 |
| 支持投影 | 无序实体对按保留三元组支持计数；passage-entity 用存在性；不保留无来源支持的同义边权 | 两项联合消融也保留此投影，不等于恢复原 HippoRAG 图 |
| RRF | BM25 k1=1.5、b=0.75；两路各前五；等权、常数 60；忽略词面零分；同分图顺序优先 | 当前整组删除 BM25/RRF，没有逐参数搜索 |
| 窗口 | 前后三条；连续相同非空 timestamp 为边界；不同中心间不去重 | 当前整组删除窗口，不逐项拆边界或大小 |
| 附录 | 原始表面三元组 JSON；按规范化三元组去重；附位置/已有时间与固定标题 | 去附录保留位置/时间，未独立消融标题或序列化格式 |

schema 提示仍输出 cardinality，但主图不再读取该字段；暂保留原提示以免清理代码同时改变生成结果。
并发数、失败重试和作业资源等运行设置不直接当作独立算法模块计数；
聚类/输入批次可能影响模型看到的候选关系，不能简单声称这些设置在语义上没有影响。

| 消融 | 唯一改变 | 固定内容 |
|---|---|---|
| without_rrf | 移除 BM25/RRF 融合 | 原 canonical 边权、PPR、来源表示、窗口 |
| without_window | 删除邻居窗口 | 检索排序、中心原文、JSON triples 附录、来源位置与时间戳 |
| without_fact_appendix | 删除中心来源的 triples 附录及对应标题 | 检索排序、原文、来源位置与时间戳、邻居窗口 |
| without_canonicalization | 按原关系标签而非 LLM canonical 标签分槽 | discourse 分类、latest-only、边权公式、RRF、旧 reader 表示 |
| without_latest | 不删除旧来源的关系支持 | canonical 标签、discourse 过滤、边权公式、RRF、旧 reader 表示 |
| without_discourse_filter | 不删除 discourse 支持 | canonical 标签、latest-only、边权公式、RRF、旧 reader 表示 |

后三项是图部分的条件消融：旧 reader 事实附录仍来自原完整策略，不同步改变其筛选。
因此不能将其解释为“从整个 pipeline 完全移除该策略”。第二阶段如需研究整体效果，
应另做同步改变图与 reader 的明确对照，而不是混进上述单模块结果。

## 控制与完整范围

- 先完全还原旧图边权和来源文本，核对全部六任务来源后冻结所有消融图；构建不用问题或答案。
- 原始文件较旧，缺少后来添加的结构化元数据：允许重建结果多出字段，但旧字段和值必须逐项完全一致。
- 使用原 loader、split、chunking、prompt、解码、评分和 seed42；仍为 3386 题、六任务、9B/4B。
- 建图消融固定原 passage/fact embedding、识别过程、PPR、RRF 和 reader 表示；不加新 query LLM 调用。
- 每任务先通过完整旧配置的 ordinary retrieval 校验，再生成消融检索结果。
- 去掉 RRF 的已有完整候选是 `optimization_source_window_seed42_20260913/canonical_graph_source_window`。
  仅在原 case 字段、题目遍历顺序、全任务每题有序 reader 文本完全相同后复用其两个目标 reader 的原 QA。
- 其他消融若整个任务的上下文与完整配置完全相同，复用完整配置 QA；不按题拼接，也不根据分数选复跑。
- 复用 QA 不算新调用；原调用的 token 成本保留为该方法的成本。建图、检索、新 QA、复用 QA 分开记录。
- 缺失任务不补零，控制不一致直接失败，不静默放宽。两个 reader 的最大新 QA 为 33860 次；
  全任务等价检查后为 30460 次新 QA、10172 次复用。此前 2B 的研究成本另行保留，不从历史中抹去。

## 结果与后续

已有整体图对照为 `optimization_hybrid_graph_seed42_20260913/original_graph_rrf_window`：
同一 RRF、同一来源顺序、同一事实附录与窗口，仅恢复原 HippoRAG 边权。
本轮已核对全部 15 组原图边权、来源表示及全部 3386 题字段/顺序，以及目标 reader 的完整 QA。
这组已有结果用于回答图整体的条件贡献；六个新单模块对照用于解释内部作用，二者不能互相替代。
具体差值及正负结果记录在 `record.md` 的旧主配置消融部分；不是本轮新生成的 QA。

每个 reader 分六任务报告原分数、消融差值、输入 token 差值和新/复用调用数，不跨指标求平均。
同时保留既定九项完整 baseline 的逐任务原分数、最佳值和每个消融的严格胜出任务数；
不只比较旧主配置，平分不计胜出，缺少 baseline 直接拒绝汇总，不声称整个领域 SOTA。
窗口与附录消融改变 context 预算，不宣称等 token 比较；一次跨硬件运行不支持统计显著性结论。
已观察到上下文不变但 QA 评分变化，因此单次小分差不作为删减证据；保留原预测，不按题替换或选高分复跑。
最终汇总逐任务列出有序上下文不变但官方评分变化的题数，JSON 同时保留回答字符串变化的数量。
这只是已有预测的诊断计数，不是新评测指标或显著性检验；QA 内的上下文相同题数须匹配检索记录。
若候选简化仅依赖这类小差值，后续应在相同硬件/解码设置下预先确定完整控制与候选的复现实验，
固定报告全部运行，不改变现有指标、数据范围或事后选择最好的控制。
先用第一阶段结果选择需要细拆的模块，再检查 canonicalization 与 latest-only 等关键交互。
当前边权只累积实体对与 passage-entity 支持，canonical 标签只影响 latest-only 分槽：
固定旧 reader 且关闭 latest-only 后，再去掉 canonicalization 不会改变边权。
因此这两个模块不能预设为独立可加贡献；这种代码层面的等价不需要额外重复 QA。
删减后的候选必须完成 4B、9B 的六任务验证，不能把各任务最好的消融拼成一套方法。
