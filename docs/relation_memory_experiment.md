第二版检验“来源内主体分组”：同一个来源输入中的同一主体，其不同关系放在一起；不把不同来源直接混成大组。动机是保持一个对象的关联信息，并避免对话中“某人说过”跨多个场景聚成巨长条目。它仍是写入组织，不增加 Generator/QA 调用。使用相同原始三元组、位置与日期格式，固定 dense top-5 和原 QA 协议，完整六任务先跑 9B。只运行新增的 `source_subject_top5`，复用第一轮平铺对照，不重复它的 QA。

两版都不是 token 匹配比较，也未解决别名/同义关系对齐；这一轮不额外叠加 verifier。若第二版仅用更多 token 换分数，要再做预算匹配，不能凭分组名称宣称机制优越。

## 这轮真正要回答什么

同一对象的同一关系，其不同取值常散在不同记忆条目中。自由整合可能删除这些陈述；独立条目又可能只取出其中一个版本。我们先检验一个很小的写入操作：**把同一主体、同一关系的陈述组织成一条持久化记忆，全部保留，不决定哪个版本是真的。**

例如某软件的两个开发者陈述会一起保存，附各自输入位置。这里不替 evaluator 选答案，不把输入顺序直接当事件时间或真值。这个操作是普通关系分组，不应包装成新图理论或形式化保证。

它来自实际失败线索，但并不已经解决那些失败：LightMem 离线整理删除过 AppleWorks 的两种开发者陈述；另一方面，相同检索内容也出现过不同 QA 答案。前者支持检查记忆整合，后者限制从分数变化直接归因。详见 [失败分析](memory_failure_mining_and_algorithm_direction.md)。

## 用户本轮明确放宽的研究边界

允许为自己的 training-free memory 尝试 heuristic、已有组件组合，并根据已看过的多个 benchmark 迭代。不额外制造 train/dev/test 划分，不做 subset。

这种实验是**在已查看的基准上进行探索性开发与跨任务比较**，不是未见测试集的泛化证据。即使文章定位为分析论文，也如实交代开发过程、所有任务的升降和成本。不把评测问题、标准答案、题号或任务专用答案规则写入 memory 构建；不隐藏不利结果。原 baseline 的默认参数、数据转换和既有结果继续保持不变。

## 实际实现与对照

直接读取本轮已完成 HippoRAG 的 OpenIE 结果，使用同一批 Qwen3-30B-A3B-Instruct-2507 抽取事实。没有重新调用 Generator，也没有修改原 HippoRAG 的文件。

| 项目 | 平铺事实对照 | 关系分组原型 |
| --- | --- | --- |
| 保存的陈述 | 每条抽取三元组独立存储 | 按主体和关系分组，组内保留全部三元组 |
| 共同信息 | 原三元组文本、输入位置、已有对话时间记录 | 完全相同 |
| 合并判据 | 不合并 | 主体与关系仅规范空白和大小写后相等；不做实体别名推断 |
| 下游检索 | 原有 dense cosine，最终五条 | 相同 dense cosine，最终五条 |
| Evaluation Backbone | Qwen3.5-9B，non-thinking，seed 42 | 完全相同 |
| QA prompt、温度和输出上限 | 复用现有 benchmark runner | 完全相同 |

内存构建函数不接收 QA case。所有输入先形成记忆，再读取问题做检索。原文与已保存 OpenIE 的对应只规范空白：全量检查发现 MH-Doc QA 一个来源段落的双换行在已保存抽取文本中变成空格；没有改动原文或抽取事实。

这种原型是**复用 HippoRAG 抽取的独立 memory 表示**，不是官方 HippoRAG，也不是已经能无改动插入全部 baseline 的通用插件。

## 成本、公平性与尚未解决的问题

- **五个记忆条目不是相等的事实数或 token 数。** 分组可能只因返回了更多事实而变好。记录每题输入 token、事实数和时间；在预算匹配对照之前，不宣称组织机制自身胜出。
- 额外 Generator calls/tokens 为零，但完整方法成本不是零：需要计入复用的 HippoRAG 原始抽取成本。原构建 `efficiency.jsonl` 路径写进 settings，增量分组和 embedding 时间单独记录。原 HippoRAG 的完整图构建时间也不能全部算作本原型的必要成本；若现有记录无法拆开，保留“抽取成本未能精确拆分”的限制。
- QA 使用既有测量包装，记录实际输入 token、输出字符数和用时；输出字符数不冒充输出 token。Generator 此轮没有新增输出。
- 分组不丢弃已抽取陈述，不代表原始自然语言没有在抽取时丢失信息，也不能修复原抽取错误、遗漏的时间限定或说话者绑定。
- 相同字符串关系不等于相同含义；同义关系字符串又可能未被合并。宽泛关系，例如某人“说过”，可能形成较长条目并稀释 embedding。这些是预计要检查的失败，而非事后删除困难输入的理由。
- 输入顺序只是输入顺序。尤其 2Wiki 的语料排列不解释为历史时间；也不引入所有任务“后写入一定正确”的规则。
- 未添加事实补全、查询时图扩展、重排、额外 LLM 推理、输出预算修改或截断 fallback。若记忆超过 embedding 原有长度，明确报错，不偷偷裁切。
- QA 仍使用原有采样参数。相同 seed 不保证不同上下文的答案逐题享有同一随机数状态，小幅涨跌不能被过度解读。

已执行的非模型检查：全部六任务的来源范围对应；两种表示的三元组及其来源记录逐项计数完全一致；cosine 排序与原实现对照，包括零向量和并列分数。没有留下 test 文件。GPU 实际完成情况另行更新，检查通过不等于 QA 已跑通。

## 看完结果如何继续

若多任务有收益，先逐题检查组内增加了什么必要关系，以及是不是仅靠更多 token；再用相同材料与预算对照决定保留哪个构建操作，不立刻加复杂模块或宣称新颖。

若只在冲突任务改善，诚实收窄为版本并置的探索，不称普适方法。若对话任务变差，检查是否把多个事件混进同一宽泛关系；下一轮候选是保留来源事件边界，而不是换检索器或给特定题加规则。若所有任务都没有稳定收益，记录负结果，放弃当前分组方式。无论哪种结果，都不修改已经产生这一轮结果的代码或协议。

## 其他可参考 baseline，暂不启动额外生成

[SimpleMem 论文](https://arxiv.org/abs/2601.02553) 研究结构化压缩、会话内整合和查询规划，适合核对“组织能否减少使用成本”；[官方仓库](https://github.com/aiming-lab/SimpleMem) 现在还包含后续多模态与自演化版本，接入时必须选论文对应的 text 方法，不能把最新大合集默认行为当原论文。

[A-Mem（NeurIPS 2025）](https://arxiv.org/abs/2502.12110) 已有结构化笔记、链接和历史记忆演化，适合核对“动态组织”的先行工作；[作者评测代码](https://github.com/WujiangXu/A-mem) 可作后续接入入口。

当前优先把自己的最小原型跑出完整正负结果，不为增加方法名字而立刻扩展两套全量生成。普通分组、建图、版本保存都不是本项目独创；论文贡献须由具体机制与可重复的发现来支撑。
