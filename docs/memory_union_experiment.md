## 为什么转向这个实验

前两版只调整同一批 HippoRAG 抽取事实的分组方式。第二版的 LoCoMo F1 为 41.27%，2Wiki F1 为 39.75%，仍低于当前最强基线的 55.37% 和 51.87%。继续把较弱表示拼得更大，并没有足够证据能弥补差距。

现有强方法分别保存原文、抽取事实和事件。先测试它们的取回内容是否互补，再根据完整错例决定应改进哪一环节。这是**读取阶段的组合实验**，不是新的 memory 生成算法，也不是现成的论文贡献。

## 两个设置

统一使用四个来源，所有任务完全相同：HippoRAG、Mem0、AnchorMem 官方检索、第一轮的平铺三元组。直接加载已完成的 `retrieval.jsonl`，不加载旧预测，不重新构建 memory。

1. `memory_union_all`：按各来源的第一条、第二条等顺序交错排列，只对完全相同文本去重，保留全部候选。来源顺序固定为上述四种，不根据任务或正确答案切换。
2. `memory_union_dense_top5`：从同一批候选里，用既有 Qwen3-Embedding-0.6B cosine 排序取前五条；不训练 reranker、不增加生成推理。

源方法的原始分数尺度不同，不直接相加。AnchorMem 的原始输出保留其既有顺序；该输出不应额外解释为严格相关性排名。交错顺序是本轮明确记录的实用选择，不是官方融合算法。

组合函数只接收取回的文本与元数据，重排只使用问题和文本。问题、标准答案和其他 case 字段在外层用于确认四个文件对应同一批评测题，然后原样交给旧 runner；不被用于候选筛选或规则构建。

## 不改的部分

全部六任务、3,386 题，没有 subset。Evaluation Backbone 为 Qwen3.5-9B，non-thinking，seed 42。使用原有 QA prompt、温度、输出上限和官方确定性指标；不加 verifier 或第二次回答调用。原基线文件和前两轮结果保持不动。

对照的最终内容数量不同，这是有意检查信息范围的实验，不是严格等 token 比较。全量保留版如果更高，不能立即归因于组合机制。每题记录实际 QA 输入 token、输出字符和时间；输出字符不冒充输出 token。

新增 Generator calls/tokens 为零，仅指**这次复用后的增量**。完整组合系统仍依赖多个源方法的记忆生产和检索，不能把历史构建成本藏掉。源检索文件位置写入 settings，组合、embedding 和 QA 开销单独保存。
