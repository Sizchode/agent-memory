# 完整实验结果

更新：2026-09-12。本文保留既有结果，不重建 memory、不重跑 QA、不更改评分。主表包含 **8 种 baseline 设置 × 6 个任务 × 3 个回答模型 = 144 个完整评测**；另列 183 个完整探索性评测，共 327 个完整的“设置 × 任务 × 模型”结果。分类分数和复用结果不重复计数。

本次从保存的 `predictions.jsonl` 逐题核对问题数量、唯一 ID、同任务覆盖和 `summary.json` 的均值一致性；baseline 还逐格检查了 retrieval 与预测覆盖。正文可使用第 2 节主表，第 3–5 节及探索性结果可放附录。这里的完整性核对不等于重新认证所有适配与原论文完全相同。

所有效果数字均为百分制，越高越好，保留两位小数。MemoryAgentBench 是归一化后的答案子串匹配，不是整句完全相等；LoCoMo 使用类别特定规则，其中第 5 类是确定性拒答得分，而非普通 token F1；2Wiki 使用答案别名中的最高 token F1。仅按问题平均，不把三类不同指标再平均成“总分”。未计算的新指标不补造，未完成的运行不报部分均分。代码口径见 [数据入口](../dataset_loader/loader.py)、[MemoryAgentBench 评分](../utils/metrics.py)、[LoCoMo 评分](../utils/locomo_metrics.py)、[2Wiki 评分](../utils/hipporag_metrics.py)。

### 固定模型与最终回答设置

Generator Backbone 为 `Qwen/Qwen3-30B-A3B-Instruct-2507`；embedding 为 `Qwen/Qwen3-Embedding-0.6B`，1,024 维。Evaluation Backbone 分别为 `Qwen/Qwen3.5-9B`、`Qwen/Qwen3.5-4B`、`Qwen/Qwen3.5-2B`。模型权重不训练，使用 BF16、seed=42、non-thinking。BM25 和 Dense 不需要 Generator。

| 任务 | 最终回答 max_tokens | Temperature | 其他显式采样设置 |
| --- | ---: | ---: | --- |
| SH-Doc、MH-Doc | 50 | 0.7 | 沿用已保存运行设置 |
| FC-SH、FC-MH | 10 | 0.7 | 沿用已保存运行设置 |
| LoCoMo | 50 | 0.4 | sampling top_k=10、top_p=0.9 |
| 2Wiki | 2,048 | 0 | 沿用已保存运行设置 |

上述 LoCoMo 的 sampling top_k 是解码参数，不是检索条数。实验中的“前置计划／检查／搜索”是另外的显式模型调用，不是打开 thinking，也不提高最终答案的输出上限。单 seed 不提供方差或显著性结论；seed 按运行重置，并非每题重置，因此有采样的任务不能仅凭同题分数变化断言因果。

### 方法标签与必要边界

| 主表标签 | 本次实际设置 |
| --- | --- |
| BM25 / Dense | 原文检索，最终最多五条 |
| HippoRAG 2 | 官方实现经项目适配，最终最多五段原文；检索阶段还会调用模型 |
| Mem0（ADD-only） | 已接受的官方 SDK 版本的 ADD-only 流程，最终最多五条记忆；不冒充论文 ADD/UPDATE/DELETE 全流程 |
| LightMem（整理前） | 初次构建完成，尚未执行最终离线整合，最终最多五条记忆 |
| LightMem（整理后） | 在同一已构建 memory 的副本上执行官方离线整合，再检索和 QA；不是重新抽取 |
| AnchorMem（Dense top-5） | 同一 AnchorMem memory 的事实和事件按 Dense 取五条，不展开原文；这是对照设置，不是官方检索 |
| AnchorMem（官方检索）† | 五个事实展开来源原文，再追加五个事件；沿用项目统一 QA，不使用另一套 reader 或 LLM judge |

固定五条不等于固定输入 token：不同方法返回原文、事实或摘要，长度不同。† 的输出预算更大，不参与固定 top-5 组的最优值加粗。统一 backbone 和已接受的抽取 prompt 适配不作为新算法贡献。已知 Mem0 历史日期锚定问题、AnchorMem MH-Doc 一次生成截断及 Mem0 2Wiki 一次无法解析的抽取输出不因表格整理而消失；这些运行保留原结果，不作未发生的修复声明。

## 6. 探索性对照：与 baseline 主表分开报告

以下不是已经确定的新 memory 算法，也不是官方 baseline 的同预算复现。变体根据同一批 benchmark 的错题和反馈迭代，属于探索性分析，不是未见测试集上的独立泛化确认。不按任务挑最高分拼成统一方法，不宣称 SOTA。涉及多套 memory、更长上下文或额外模型调用的设置必须连同差异报告。

### 设置定义

| 编号 | 设置 | 实际改动 |
| --- | --- | --- |
| R1 | 平铺三元组 top-5 | 只用 HippoRAG 已存抽取事实，按原 embedding 取五条。 |
| R2 | 主体—关系分组 top-5 | 同一批事实按主体和关系分组，取五组；组大小不等于五条事实。 |
| R3 | 来源—主体分组 top-5 | 同一批事实按原文来源和主体分组，取五组。 |
| A1 | 多来源合并 | HippoRAG 原文、Mem0、AnchorMem 官方输出及 HippoRAG 平铺事实交错合并、文本精确去重；需要三套方法的 memory。 |
| A2 | 合并后 Dense top-5 | 从 A1 的候选集合按原 embedding 选五条。 |
| B1 | 合并＋前置计划 | A1 证据不变，回答前增加一次同一 Evaluator 调用，temperature=0、max_tokens=128。 |
| B2 | 合并＋前置检查 | A1 证据不变，增加一次检查调用，temperature=0、max_tokens=128。 |
| C1 | 合并＋图连接五条 | A1 加最多五条实体端点相连的已有事实；候选仍按原 embedding 排序。 |
| C2 | 合并＋Dense 追加五条 | A1 加最多五条全库 Dense 事实，是 C1 的新增条目数上限对照，不是逐题 token 匹配。 |
| D | 合并＋两次搜索 | 每次生成最多 64 token 的查询，再 Dense 取最多五条新事实；两次额外 Evaluator 调用。 |
| E | 合并＋来源标记 | A1 内容和顺序保留，增加原文／生成记忆标签及阅读提示；不增加调用。 |
| F | 单套记忆：原文＋事实 | 仅 HippoRAG 五段原文及同次抽取的五条事实，不依赖 Mem0／AnchorMem。 |
| G1 | 合并＋两步图连接 | A1 上从问题相关端点展开两轮、每轮最多五条已有事实；无额外模型调用。 |
| G2 | 合并＋Dense 追加十条 | A1 加最多十条全库 Dense 事实，作为 G1 的条目数上限对照。 |
| H1 | 合并＋路径展示（后置） | 与 G1 选择相同事实，按连接路径展示并重复必要前驱；放在原证据之后，token 数会改变。 |
| H2 | 合并＋路径展示（前置） | 与 H1 相同路径内容，改为放在原证据之前。 |
| I | 单套记忆：事实＋对应原文 | F 加上所取事实的准确来源原文，只复用 HippoRAG memory。 |
| J | 合并＋路径＋对应原文 | H1 加上路径事实的准确来源原文；无额外调用，但上下文更长。 |
| K | 路径＋来源阅读提示 | J 的检索内容不变，提示区分存储位置、事实版本和事件时间。 |
| L | 局部上下文两次搜索 | 与 D 一样两次 64-token 查询，但查询只看问题、初始五条、最新五条和先前查询；最终 QA 保留完整证据。 |
| M | 单套记忆：路径展示 | 只用 F 的 HippoRAG 原文和事实，重新选择起点后做两步连接和路径展示。 |

所有探索设置复用已有抽取产物；“无额外调用”只指这一读取改动，没有抹去源方法的 memory 构建和原检索成本。A–E、G–H、J–L 依赖三套方法的 memory；R1–R3、F、I、M 只依赖 HippoRAG 抽取。Plan／Check／两次搜索均使用对应表的同一 Evaluator，最终 QA 参数仍见第 1 节。

## 7. 从这些结果能说什么

HippoRAG 2 在 2Wiki 的三个 Evaluator 上都领先本批 baseline，并有更高的原文 Recall@5；这支持其多跳证据检索价值，不证明抽取一定更忠实。Mem0、AnchorMem 在事实更新或对话任务各有优势，但没有一个 baseline 覆盖所有任务。LightMem 离线整理没有带来稳定提升，不能仅凭“执行了整理”假定记忆更好。

探索性图连接 C1 在 2Wiki 的 9B／4B 分别为 58.04／55.53，Dense 追加五条 C2 为 51.95／51.07；在 LoCoMo 则没有对应优势。B2 的 LoCoMo 总分 64.75 高于 A1 的 59.41，但其对抗拒答类由 69.06 变成 92.38，不能写成记忆构建普遍改善。FC-MH 的所有 baseline 都很低；J 的 9B 达到 17.00，但依赖三套 memory 和更长上下文，尚不是单方法、等预算的改进证据。

这些表可以作为明确标注上述适配、单 seed 和探索边界的实测材料；不能直接与其他论文的不同 backbone、不同 QA 协议或 judge 分数作数值排名。当前研究方向仍是先检查生成记忆的质量差异，再决定独立 memory 算法或单方法可插拔模块，见 [研究计划](research_plan.md)。本次只补全报告，不重启已取消实验。
