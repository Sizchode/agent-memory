# 先检查生成记忆的质量，再决定算法

更新：2026-09-12 UTC。当前阶段是分析方案；没有启动新的 Generator、memory 构建或 QA 实验。

## 当前决定

所有本轮运行和排队作业已按用户要求取消，取消后核对 `squeue` 为空。已生成的 memory、完整结果、部分输出和日志均保留，不删除、不覆盖、不把部分输出当成完整成绩。

不再以拼接多个 baseline 的检索结果作为新方法主线。接下来先检查原始输入经过不同生成流程后，哪些信息被保留、遗漏、误写或在整理中损失，再决定是否需要新的 memory 构建机制。暂不选定图、超图、compiler 或 verifier 框架，也不因一个例子就全面重建 memory。

## 之前实际做了什么

已有强分支合并了 HippoRAG、Mem0、AnchorMem 各自的检索结果，以及来自 HippoRAG 抽取的平铺事实，再进行图扩展、路径展示、补原文或回答前检查。这主要是多方法 ensemble 和读取阶段实验。

同一个一跳图版本在 9B／4B 的 12 个组合中有 11 个超过本地 baseline 的最高点估计，但它依赖多套 memory 的构建与检索，不能将这个结果称为独立 memory 构建算法的成绩。也没有证明它是分别适用于 Mem0、LightMem 和 HippoRAG 的通用插件。

这批实验仍可用于发现来源互补、证据干扰和读出失败，但不再通过继续拼接组件来代替对 memory 生产的研究。

## 术语与比较对象

- **Generator Backbone**：读取原始文章／对话，执行抽取、压缩、整合或更新的固定模型。
- **Memory 生成流程**：决定模型看到哪些内容、执行什么操作，以及如何组织和保存输出的算法与适配流程。
- **Evaluation Backbone**：消费 retrieval／memory，输出下游 QA 答案的固定模型。

现有主要对照使用统一的 Qwen3-30B-A3B-Instruct-2507 Generator。因此首先比较的是同一 backbone 在不同生成流程下的产物，而不是给不同 Generator 模型排能力榜。若之后要比较 backbone，必须固定同一流程和输入协议后再换模型；当前尚没有这样的受控结论。

## 尚待验证的机制假设

**把原话解释清楚，与把信息压缩变短，是不同操作；把两者混在自由改写中，可能产生不必要的信息损失。**

“昨天参加活动”需要原生时间参照才能独立理解；多次任职经历需要保持各自公司与年份的对应。与此不同，将这些内容合并成短摘要会主动舍弃细节。当前要检查两类操作实际在哪些产物中发生、造成了什么影响，而不是预先认定所有压缩都有害。

若证据支持这一问题，可尝试先形成忠实且可独立理解的记录，再通过引用、组织和去重复用它们，减少后续反复自由改写。图只是可能的组织方式；该机制未实现，也尚无新颖性或效果结论。Compiler 暂不作为论文主线；不能用程序语义保持的类比替自然语言抽取提供正确性保证。

## 下一步的分析顺序

1. **对齐同一份输入。** 对单独的方法检查原文、初次抽取、整理后 memory、实际 retrieval 和最终答案。既看失败也看成功对照，不混合不同方法的证据代替单方法能力。
2. **定位变化阶段。** 分开记录原文有而抽取缺失、抽取误写、整理删除或错误合并、已存未取出、证据已给出但回答失败，以及官方标注或适配问题。缺少中间产物时标为无法判断，不猜测。
3. **比较流程差异，不先给模型贴强弱标签。** 同一 backbone 下，关注生成输入、上下文解释、压缩、去重与整合操作。格式合法、条目更多或答案字符串出现，都不能自动等同于语义质量更高。
4. **选一个有证据支持的问题。** 只改变相应生成／整理操作；受控实验保持输入、Generator、检索实现、Evaluation Backbone 和既定最终回答预算。memory 内容变化是实验变量，同时报告实际长度与构建、检索、QA 成本。
5. **再跑完整既定评测范围。** 六任务、三个 evaluator 的范围与官方确定性指标不变；人工检查只是诊断，不构造一个新 benchmark 子集，不把未跑或中断的任务记为完成。

不用 LLM judge 给 memory 打一个缺乏依据的质量总分，不将自造语义标签变成官方 metric。人工个案分析和最终官方 QA 结果分别呈现，不伪装成完全自动、无歧义的质量测量。

## 后续方法必须满足的边界

- **若做插件**：每次只接一个方法的 memory／检索产物，分别比较该方法加模块前后，不能暗中借用其他 baseline 的证据。需要新增抽取或语义转换时明确计入成本。
- **若做独立完整算法**：从原始输入经统一 Generator 建立自己的持久化 memory，再检索和回答，不要求其他 baseline 同时运行。
- 哪条路线更合适由产物分析决定。此前倾向独立算法，但没有据此选定 schema、建图机制或启动全量重建。
- memory 构建不读取评测问题和答案；问题只用于读取阶段，标准答案只用于评分与诊断。不得写入题号规则、答案或按 benchmark 择优路由。
- 可以使用有明确依据的 heuristic 或已有组件组合，但不能把它们的效果、普适性或新颖性预先写成结论。

若主要失败来自适配、retrieval 或 reader，而不是 memory 生产，就应收窄主张或改变研究问题，而不是强行给 Generator 或图结构安排一个故事。
