# 训练自由记忆：证据组合、关系连接与回答校验

当前状态（2026-09-12 UTC）：所有剩余运行、排队及后继作业已按用户要求取消，已有产物保留。多方法合并属于 ensemble，不再作为独立 memory 算法主线；“11/12 领先”不能证明新的 memory 构建机制有效。下一步见 [Generator 与 memory 质量检查计划](generator_memory_quality_review.md)。第二轮的部分完成情况见 [已停止的第二轮记录](memory_improvement_round_two.md)。本文件是历史探索报告，保留各分支及其失败，不按任务拼接最高分。

## 研究范围与比较口径

本轮研究窗口为纽约时间 2026 年 9 月 11 日 19:19–22:19。目标是在完整、固定的评测范围中检验可执行的改进，而不是预先为某个结构宣称优越性。数据包含 MemoryAgentBench 的四个任务、LoCoMo 和 2Wiki，共六任务、三个数据来源家族、3,386 题。六任务不等于六个完全独立的数据集家族。

这里的 2Wiki 是 HippoRAG 官方 `reproduce/dataset/2wikimultihopqa.json` 发布的 1,000 题和对应 6,119 段语料，不是 2Wiki 原始训练／开发／测试集的并集。本轮没有另抽子集，也没有根据新方法表现删题。“全量”仅指完整既定评测范围。

所有新增方法保持训练自由，先统一使用 Qwen3.5-9B。原始记忆生产仍复用 Qwen3-30B-A3B-Instruct-2507 的已保存输出。原 baseline、评分函数、QA 输出上限与默认采样设置不改变；研究方法的额外操作、prompt 和预算单独记录。最终答案按已有 Substring Exact Match 或官方 answer F1 评分，不用 LLM judge。

这些任务已经被用于查看错例和开发方法，因此结果属于探索性基准开发，不作为未见测试集泛化。构建和推理代码不得根据标准答案、题号或逐题规则选输出。已有官方 prompt 中的示例及 LoCoMo 选择题选项继续原样保留，不将其误称为新增答案注入。

逐题比较工具中的“相同上下文”计数只比较取回文本及其顺序，不包括之后附加的计划、检查笔记或指令。B 与 K 就有意改变了后者；不能因为取回文本相同，就把它们的所有分数变化归于随机采样。已完成单元还核对了题目覆盖、题号唯一性和逐题官方分数与汇总的一致性。

LoCoMo 类别 5 的发布数据 `answer` 是干扰选项，不能读成应该输出的 gold answer；官方评分要求拒绝不受对话支持的回答。新增分析字段 `answer_field_role=adversarial_distractor` 和 `expected_behavior` 明确标注这一点，保留发布字段原样。没有改变官方选择题 prompt、标签或评分，也没有因为这项分析标签澄清重跑 QA。

## 进入本轮时的证据

第一版按“主体、关系”分组，第二版按“来源、主体”分组，保存同一批完整三元组。第二版在 LoCoMo 和 2Wiki 分别为 41.27%、39.75%，明显高于同批事实平铺的 36.13%、33.14%，但仍不及既有强 baseline。单跳事实更新的平铺已为 72%，分组只有 73%，不能把相对旧基线的全部差距归因于分组。

在 LoCoMo，跨来源关系分组平均输入 2,143 token，分数 35.35%；来源内主体分组平均 683 token，分数 41.27%。这支持检查过宽分组的代价，但单凭这些均值不能确定是事件混合、排序还是具体信息覆盖导致变化。

## 实验 A：合并强方法的取回内容

统一合并 HippoRAG、Mem0、AnchorMem 官方检索和已保存的平铺三元组，按固定来源顺序逐位交错排列、精确文本去重。四个来源中的平铺三元组复用 HippoRAG 的抽取，因此生产成本不能重复计入两次。另有从同一候选集合中按原 embedding cosine 选前五条的对照。

截至 19:57，合并全部证据与 dense 五条对照的六任务均已完整完成。

| --- | ---: | ---: | ---: |
| 单跳文档问答 | 93% | 86% | HippoRAG 88% |
| 多跳文档问答 | 67% | 46% | HippoRAG 59% |

至少存在有用的来源互补，但单一统一策略并未在所有任务同时最佳。这里不按任务选择较高分的一支并冒充一个方法。全部证据与五条证据的上下文成本不同，也不视为纯机制的等预算对照。

逐题比较也保留退步：LoCoMo 相比 AnchorMem 官方版，529 题分数提高、348 题降低、1,109 题不变；2Wiki 相比 HippoRAG，70 题提高、54 题降低、876 题不变。差值不是纯粹的召回因果效应，还包含证据排序、冲突、上下文长度与采样变化。单 seed 的小差距不声称显著。

2Wiki 的原文证据检查进一步发现：HippoRAG 已找齐 gold passages 的 469 题，合并前后 F1 为 70.45% / 71.38%；合并后新找齐的 12 题为 68.06% / 85.83%；仍未找齐原文的 519 题为 34.71% / 35.24%。最后一组也可能有生成记忆中的有效证据，因此“未找齐原文”不等于答案信息完全缺失。合并对原文覆盖的提升较小，不能把全部收益解释为召回提高。

成本方面，LoCoMo 合并全部证据平均 QA 输入 2,650.5 token，而 AnchorMem 官方检索为 1,823.5；2Wiki 对应 2,839.3 / 1,919.0。这里的旧 AnchorMem 两个完成单元曾误把张量维度记为 2，已用原 tokenizer、原 prompt 和原检索精确重计，只修正计数，没有重新生成或修改预测。增量合并不调用 Generator，但完整方法仍需要计算 Mem0、AnchorMem 和 HippoRAG 的原始构建成本。

运行入口与具体文件见 [证据组合实验](memory_union_experiment.md)。GPU 数组 `6255569`；成功结束后由 `6255651` 自动导出完整对照和逐题分数变化。

## 实验 B：同一证据上的推理与校验对照

目标是区分“取回内容不够”与“已有内容未被正确组合”。固定实验 A 的全部取回内容，分别增加一次短证据计划或证据检查，再按原 QA 协议回答。

两个新增设置为 `memory_union_plan128` 和 `memory_union_check128`。前置步骤同样使用 Qwen3.5-9B、non-thinking、temperature 0、最多 128 新 token；最终回答保留原 benchmark 的输出上限和采样。额外笔记明确标为未经验证，不能当新事实。接口不接收 gold answer 或任务编号。每次调用记录实际输入/输出 token、用时和是否用尽前置预算；不把输出字符数冒充 token。

这是简单的两调用对照，不是 IRCoT 或 Self-Refine 的官方复现：没有交错检索，也没有多轮反馈循环。IRCoT 的先行工作说明多跳检索与推理可以互相依赖；Self-Refine 说明额外反馈与修订无需训练，但不能据此预设本次设置有效。[^1][^2]

数组 `6256335` 先启动两个长任务。三个短任务在模型加载阶段失败，没有预测产物：一次缓存文件读取异常，两次 GPU 初始化异常。确认本地四个权重分片完整后，重试限定离线缓存；`6256353` 在 gpu4001 仍发生 GPU 初始化错误。随后改在独立 B200 节点重试，算法、模型、精度和预算没有改变。正常运行的任务未取消。

`utils/models.py` 仅新增两个实际 token 计数字段，位置在原 generate 返回之后；没有改变模型输出、解码参数或评分。

短任务已有完整结果：计划 / 检查的 SH-Doc QA 为 95% / 93%，MH-Doc QA 为 66% / 67%，单跳事实更新均为 73%。与不加前置步骤的 93% / 67% / 71% 比较，目前没有一致提升。两个长任务的检查分支单独放在 `memory_reasoning_check_seed42_20260911`，与原计划分支并行，避免同一卡串行等待。

实际响应也说明不能仅凭命名认定执行了“计划”：某些文档和事实题的前置步骤直接输出一个答案；2Wiki 的前置步骤则持续写详细分析，目前均用满 128 token。两者都按原样记录，不中途扩大上限。这里应称为前置 prompt 干预实验，而不是已验证的可靠推理机制。

计划分支的六任务现已全部完成：单跳文档 95%、多跳文档 66%、单跳事实更新 73%、多跳事实更新 5%、LoCoMo 61.2431%、2Wiki 53.60%（完整精度见 JSON）。它在 LoCoMo 高于不加前置调用的 59.4094%，但没有一致改善六任务。两份计划作业在完整结果落盘后暂停了原本会重复执行的检查阶段；正式检查仍由独立作业执行，不将非正式目录的一条或零条预测当作结果。

## 实验 C：关系图连接与等新增条目数对照

已实现一个小型实体连接索引：把原三元组主体、客体按规范空白和大小写后的文本建立索引，保存到 JSON。查询以已有平铺检索的五条事实为起点，找“前一条客体等于后一条主体”的正向连接，以及对应反向连接；不生成新事实，也不推断别名。

候选事实按原 embedding cosine 排序，最多追加五条到实验 A 的全部证据。对照则不限制图连接，从整个相同事实库中选最多五条尚未出现的事实追加。两者保留全部原证据，最终 QA 不增加额外调用。它们比较的是候选选择方式；新增条目数相同的上限仍不等于完全相同的 token 数。

全量软件检查已验证每一条连接共享真实端点、没有将 seed 当作新增事实。各任务每题平均图候选数为 27.7、12.7、32.7、47.1、411.4、16.0。LoCoMo 的高连接度预示泛化风险：常见人物或普通词可能连接很多不相关记录。该现象需要从结果判断，不通过测试题专用规则绕过。

这不是超图方法。HyperGraphRAG 已将多元关系建成超边，HGMem 则在查询相关的工作记忆中更新、插入和合并记忆点；简单文本分组或两条边连接不能冒充这些机制的新发现。[^3][^4]

LoCoMo 的完整结果为图追加 59.4027%、dense 追加 59.5659%，原合并为 59.4094%。当前没有图选择优于简单 dense 追加的证据，也不能把 dense 的约 0.16 个百分点提升解释成已验证收益。

2Wiki 的完整结果为图追加 58.04%、dense 追加 51.95%。图版在此任务优于向量追加，但在 LoCoMo 没有优势。图版六任务分别为 94%、66%、75%、5%、59.4027%、58.04%。它与 G 的两步图在 2Wiki 相差不足 0.2 个百分点，不能声称更多展开步骤已经被证明更好。

与向量追加五条逐题比较，2Wiki 有 101 题分数提高、23 题降低、876 题相同。平均 QA 输入分别为 2,946.14 与 2,973.88 token，平均输出为 10.73 与 11.74 token。图版不是通过更多平均 QA 输入获得这组差距。LoCoMo 则有 26 题在检索文本相同的情况下改变得分，提醒我们其采样设置下不能逐题直接作因果归因。

退步案例也与机制有关：Sara Ali Khan 的继母一题，原文完整保留父亲先娶 Amrita Singh、后娶 Kareena Kapoor 的信息。图追加后仍有这些原文，并增加两条婚姻关系，模型却由正确的 Kareena Kapoor 改为祖母 Sharmila Tagore。这里不是新增事实凭空写错，也不是正确婚姻信息完全没取回；共享人物的不同亲属关系被错误使用。相同实体连接不能自动保证关系角色组合正确。

为了验证读出模型依赖，作业 `6262090` 在现有 4B 长任务释放 GPU 后运行 C 的图版和向量五条版，覆盖六任务、每批四个独立读出进程。它只读取已保存检索，不增加新的算法设置，也不超过六张分配 GPU。

上述 4B 对照现已完整完成：图连接／向量追加的单跳文档问答为 90／90，多跳文档为 62／61，单跳事实更新为 57／59，多跳事实更新为 8／6，LoCoMo 为 53.8826／53.6116，2Wiki 为 55.5293／51.0721，均为百分制。2Wiki 的图连接收益跨两个 evaluator 出现，但不能称作每个任务都优于向量追加。

## 实验 D：读取时搜索缺失关系

另一个统一对照在完整的合并证据上，连续两次生成“下一条最需要查找的关系”的搜索问题，每次最多 64 token，再从同一批已保存三元组中 dense 取最多五条新事实。第二次可以看到第一次补充的事实；所有原证据保留，最后使用原评测器回答。查询模型同为 Qwen3.5-9B，non-thinking、temperature 0。额外调用与输入、输出 token、检索时间逐题保存。

它不通过标准答案决定搜索内容，不使用按题号规则，也不以数据集名称切换算法。仅原 prompt 的任务政策保持原样。源记忆没有重建；这是读取阶段的三调用流水线，不能当成零额外推理成本的记忆构建改进，也不能冒充 IRCoT 官方复现。用途是判断缺失关系能否通过问题相关的连续读取弥补，再决定是否值得把可复用连接提前保存。

一个已经核实的断链例子是 `factconsolidation_mh_262k_no0`：已有抽取记忆中保留了 Christian Abbiati → cornerback → field hockey → Philippines 这条链，以及旧的 goalkeeper、American football、England 等陈述。初始检索主要包含人物的两个职位，没有把后续关系一并给出。这里至少有一个具体案例不需要重新抽取才能补链。这个例子只进入分析文档，没有进入查询 prompt 或算法规则。

## 实验 E：显式区分原记录与生成记忆

LoCoMo 的实际错例中，原记录是 5 月 8 日说“昨天参加了支持小组”，AnchorMem 的生成摘要却写成 5 月 8 日参加。Mem0 提供 5 月 7 日的正确记忆后，合并结果从 0.667 F1 变为 1。该例说明 memory creation 的解释错误确实存在，不能全部归入回答模型的问题。

因此增加一个非常小的统一模块：给原文段落标记“原始记录”，给生成的摘要和三元组标记“生成记忆”，并明确提醒两者冲突时检查原记录、区分记录时间与事件时间。原文字节内容、条目顺序和数量都保留；没有额外 LLM 调用。完整 78,050 个返回条目已通过内容保留的软件检查。这个实验仍包含读出指令改变，不能把结果单独归因于存储结构。

另一些分数降低不等于事实能力降低。例如 `conv-26-41` 的标准答案为“20 July 2023 前的周二”，合并后输出正确的日历日期 July 18, 2023，F1 却由 0.60 降至 0.50。相反，`conv-26-7` 从单词 Single 变成长句“未婚、准备收养孩子”，F1 从 1 降至 0。必须同时保留官方 token F1 和人工错例解释，不偷偷改 metric，也不针对这些题写替换规则。上述是可核查示例，不是经抽样得到的失败占比。

## 实验 F：只用一套抽取记忆的双视图

为了检验昂贵的多方法组合是否必要，另跑 `hipporag_passages_and_facts`：仅组合 HippoRAG 的五个原文段落和同一套 OpenIE 的五条平铺事实，仍固定交错顺序和精确文本去重，六任务规则一致。这个对照不依赖 Mem0 或 AnchorMem 的生成产物，也不增加模型调用。它只检验本地保存的两种读取视图是否互补；并非重新实现官方 HippoRAG 的另一个版本。

已完成的单跳／多跳文档问答为 90%／62%，单跳／多跳事实更新为 71%／4%，LoCoMo 为 51.31%。LoCoMo 高于 HippoRAG 的 50.41%，仍明显低于合并全部方法的 59.41%。不能将较便宜与当前效果最强混为一谈。

## 实验 G：问题附着的两步图连接

实验 C 和 D 的完整多跳事实更新结果分别为图追加 5%、dense 追加 4%、两次查询 5%，没有解决断链。两次查询中的部分轨迹反复查原实体，例如第一题没有从人物的已知职位转向下一关系。这不是底层事实完全未被抽取的证据。

下一轮 `memory_union_question_paths2` 从初始五条事实中保留端点确实出现在问题里的起点；没有匹配时使用原五条。沿原图连接走两步，每步最多追加五条未出现的事实，始终按原问题的 embedding cosine 排序。对照从相同事实库直接追加最多十条。它是明确的启发式，不是新的数学定理；端点文字匹配、起点筛选、步数和条目预算均固定用于六任务。词面匹配可能漏掉别名，比较问题也可能有多个起点，不能提前声称普适。

此实验从原事实用与 C 完全相同的函数建立端点索引，并复用原事实向量，不调用 Generator 或额外的查询模型。原先读取 C 的索引文件，随后为解除排队依赖，改为直接从已保存事实计算相同索引；对已有文件逐组检查，内容完全相同。事实连接保存在逐题 metadata，可检查每一步是否共享真实实体。没有根据标准答案构建路径。它同时改变起点选择和展开深度；即使提高也不能单独归因于其中某一步。

完整多跳事实更新结果为两步图 6%、dense 十条 3%。100 题中 92 题有问题端点匹配，图版平均追加 8.67 条，并非每题都追加十条。第一题已取回正确的 field hockey → Philippines 关系，仍输出 Italy；该输出与另一条经过旧职位的路径相容，但不等于已经观察到模型内部的推理过程。这至少说明该题不能再仅用“没有任何正确路径”解释。

2Wiki 的完整结果给出了更明确的正面信号：两步图为 57.85%，dense 十条为 51.32%，原合并为 52.80%。与 dense 对照逐题相比，115 题 F1 提高、35 题降低、850 题相同；其中 65 题从 0 到 1，24 题从 1 到 0。图版平均只追加 7.564 条，QA 平均输入 3,038.3 token，均低于 dense 的 10 条和 3,107.8 token。因此这组优势不能仅解释为平均输入更多，但仍不是所有单题完全等 token 的实验。

具体例子包括 Mugain 的婆婆、The Straw Hat 作曲家的去世地点、An Event 导演的孩子：图版找到的连接支持了正确答案，dense 追加版本分别拒答或选错人物相关信息。退步也存在，例如 Lisbeth Palme 丈夫的出生地从 Stockholm 变成更宽泛的 Sweden。完整逐题文件位于 `agent-memory-analysis/dense_ten_to_question_paths_20260912`。

## 实验 H：把已选路径按关系连接展示

不增加任何新的唯一事实，只把 G 的已选路径作为完整陈述组展示，并明确保持原关系方向和来源位置。这样原来分散在不同条目中的中间关系共同出现。两个版本仅比较路径组放在原证据后面还是前面；这两个版本的事实及重复次数一致。它们相对 G 重复了一部分路径祖先事实，因此与 G 的 token 预算不相同，仍需记录成本。

路径形式进入 prompt 是 PathRAG 已有的思路；其选择路径的算法与这里不同，本轮不是官方复现。HopRAG 也已研究检索过程中沿逻辑连接展开。[^12][^13] 本轮用途是检查“连接选到了，但摊平后未被正确使用”的具体问题，不把路径字符串或图遍历本身作为新颖性。

多跳事实更新完整结果为路径放在后面 15%、放在前面 8%，而 G 为 6%。这是目前值得跨任务核验的信号，但只有 100 题、一个 seed；不将其称作显著提升或通用最优。两个位置版本重复的事实完全相同，读出顺序本身不能被忽略。

## 实验 I 与 J：把抽取事实重新连接到真实原文

I 的 `hipporag_facts_with_sources` 在 F 的原文五条和事实五条之外，加入这五条事实在 OpenIE 中保存的真实原始片段。只按原生来源 ID 查找，没有再检索“看起来相似”的文档，也没有生成来源。全部 16,930 条初始选中事实都检查过原生来源可解析。它只需要 HippoRAG 已有的一套抽取，不依赖 Mem0 和 AnchorMem。

J 的 `memory_union_paths_with_sources` 则保留 H 的完整路径上下文，追加路径所有节点的原始片段，精确去重，不截断来源。它检验路径已经存在后，补回抽取时省略的日期、说话人和事实序号是否有益。没有硬设“新版本必然正确”或“原文必然压过摘要”的策略。这里仍要计算较长 QA 输入的成本，不能说免费提升。

新增来源的平均字符数在 LoCoMo 为 2,163、2Wiki 为 2,376、多跳事实更新为 21,410。最后一项的原始块混有很多其他事实，因此补回来源也可能引入干扰；这只是运行前的长度检查，不是提速或准确率结论。I 与 J 均没有额外 Generator、查询模型或 embedding 调用。

J 的多跳事实更新为 17%，相比 H 的 15% 多两题。这个幅度不足以单独确定有效性；原文补回也明显增加输入长度。其单跳文档问答为 90%，低于 H 的 92%，所有退步同样保留。

J 的完整 2Wiki answer F1 为 60.7903%，H 为 57.2639%，G 为 57.8459%。J 的平均 QA 输入为 3,808.17 token，H 的前置路径顺序对照为 3,435.86，G 为 3,038.32；这不是等 token 的比较。多跳关系的原文信息有用，但不能把全部差距归因于来源链接本身，更不能声称无成本提升。路径展示也没有在 2Wiki 稳定优于平铺已选事实。

I 的 2Wiki 已完整完成，F1 为 53.34%，相比 HippoRAG 的 51.87% 高约 1.47 个百分点。它没有用 Mem0 或 AnchorMem 的构建产物，值得继续核对不同模型上的表现，但不是同硬件、同总检索成本的已完成效率证明。

## 实验 K：分开存储编号与事实版本编号

多跳事实更新的一个实际来源片段中，`Source item 209` 内的相关事实编号是 `7164`，`Source item 227` 内则是 `7774`。存储块位置和任务定义的事实版本号属于不同编号体系。即便代码没有比较它们，读出模型仍可能误解展示方式；这是待检验的解释，不能直接认定为全部错误的原因。

`memory_union_paths_source_policy` 保留 J 的检索内容原样，只添加统一说明：存储块编号不等于事实编号或事件日期；任务要求比较事实版本时，应使用原文中的事实号；记录时间与事件时间也须区分。六任务使用同一说明，没有按题号或答案切换规则。它属于 prompt 对照，不作为新建图算法，也不改变最终回答预算。

这个说明在多跳事实更新上的完整结果只有 11%，低于不加说明的 17%。因此不能把“编号解释不清”作为已经验证的主要病因，也不能仅凭措辞合理就把它加入最终方法。

## 实验 L：给搜索模型一个小型工作记忆

D 的完整多跳事实更新轨迹中，29／100 题的两次查询完全相同。L 的 `memory_union_frontier_queries2` 因此只改变搜索阶段的输入组织：保留原始问题和初始五条事实，第二次搜索再看到刚取回的五条事实及上一次查询。搜索模型不再反复读取完整多方法合并文本，也不接收最终回答格式说明。它仍使用 D 的同一搜索指令、两次调用、每次最多 64 token、temperature 0、同一 cosine 检索和每次最多五条新事实。

最终 QA 仍接收原始全部合并证据和最多十条新增事实，没有删掉原证据。原 benchmark 的回答规则照常执行。这里检验的是查询阶段工作记忆的内容组织与成本，不是训练 retriever；它也不保证每次真的搜索到了新关系，实际查询继续逐条记录。脚本为 `experiments/run_frontier_query_memory.py`。

两种搜索流程仍有相同的失败例子：第一题的紧凑工作记忆版本连续两次询问 Christian Abbiati 的 country of origin，未沿已知职位向后推进。因此“小工作记忆”目前只是明确的输入成本对照，不是已经解决规划问题的机制。运行中的局部平均输入减少不能代替完整任务的最终分数或独占 GPU 速度比较。

## 实验 M：去掉多套生成记忆的依赖

`single_source_path_bundles` 把与 G/H 相同的两步图选取和路径展示用于 F 的基础证据，即 HippoRAG 的五条原文和同一次抽取中的五条事实。图扩展重新以这个基础集合做精确去重，不挪用依赖四来源合并的旧选取结果。六任务只运行同一个最终路径展示版本；没有额外 Generator 或查询模型调用。

它检查一个具体效率假设：是否能保留连接选择的作用，同时省掉 Mem0、AnchorMem 的整套生成。原来的完整多方法版本仍保留作为对照，若便宜版本退步就按实际退步报告。这里的“单来源”指只用一套 HippoRAG 抽取，不是只看一篇文档。入口为 `experiments/run_single_source_paths.py`。

软件层面同步移除了 F/I 构建入口对未选中 Mem0、AnchorMem 文件的读取，避免算法虽然不使用其内容、程序却仍要求这些文件存在。默认完整组合入口不改变；全部 3,386 题的实际选中记录已做相等检查，清理不改变已有预测，不重跑完成的实验。

M 的完整 2Wiki 结果为 57.1546%，F 为 53.0131%，使用三套记忆的 H 为 57.2639%。M 的平均 QA 输入为 2,286.52 token，H 为 3,435.86。这里能省掉 Mem0 与 AnchorMem 的构建依赖，且在这个任务上接近 H；但不能推广到全部任务：单跳事实更新 M 为 56%，低于 H 的 72% 和 F 的 71%。多跳文档 M 为 67%，单跳文档为 85%，多跳事实更新为 11%，对话仍需完整评测。

## 构建成本与换读出模型的检查

单套抽取视图的主要动机是省掉其他记忆方法的生成，而不是把新增处理时间冒充完整系统时间。原始成功调用记录中的构建 token 如下；表内为实际输入＋输出，不包含检索阶段和最终 QA，也未加入 AnchorMem。

| 数据集 | HippoRAG 构建输入／输出 token | Mem0 构建输入／输出 token |
| --- | ---: | ---: |
| LoCoMo | 4,599,612／850,619 | 53,827,637／1,177,162 |
| 2Wiki | 5,863,801／1,933,532 | 57,564,411／1,288,970 |

为检查结果是否仅依赖 9B，数组 `6260121` 在一张现有 GPU 释放后启动，统一以 Qwen3.5-4B 评测 A 的完整合并、H 的路径展示、I 的单套事实与来源、J 的路径与来源，四个方法均覆盖六个完整任务。复用同一 `retrieval.jsonl`，不重新选证据、不重建 memory。仍使用 seed 42、non-thinking 和原 benchmark 的最终回答设置。入口为 `experiments/evaluate_saved_memory.py`；单独保存该次读出设置及实际调用 token。4B 不是未见数据集，仅是不同读出模型的检查。

## 一个已经出现的负面结果

4B 的完整 LoCoMo 结果提供了另一个重要限制。A 的完整合并为 53.2902%，H 的路径展示为 53.0348%，J 的路径与原文为 52.1796%。按官方类别拆开，J 相对 A 的多跳为 46.94% 对 44.39%、时间为 48.03% 对 48.08%、开放领域为 19.03% 对 17.69%、单跳为 66.88% 对 65.50%，但 446 道无答案的对抗问题由 47.31% 降至 37.89%。因此，总分下降主要来自这类题；更多相关内容并不保证模型更能判断答案是否受对话支持。不能据此删除该类别或按类别切换方法。

这些不同类别包含不同题目，不是人为新分组。它们说明应区分“取回更丰富的关联内容”和“支持问题所要求的确切关系”。后者仍包含读出模型行为，当前还没有一个已经验证的记忆模块能同时解决它们。

E 的来源标签在单跳事实更新上从 A 的 71% 降至 39%，多跳文档问答从 67% 降至 63%，2Wiki 从 52.80% 降至 50.00%。例如 Adam Putnam 的学校由正确的 Federal University of Rio de Janeiro 改为 University of Florida；后者确实出现在较旧原文中，而新学校存在于生成记忆。Jasper Fforde 的语言也从 Kannada 改回 English。它们与“标签诱导偏信旧原文”的解释相容，但本轮没有观测模型内部过程，也有采样差异，不能将全部下降归为同一个原因。

因此，只保存类型标签不够。需要保留具体陈述与其具体来源之间的对应关系，不能把一段未覆盖新事实的旧原文，当作反驳所有新记忆的依据。这是继续做 I、J 的动机，而不是先验保证它们会成功。

还有一类必须和实际答对区分的变化：2Wiki 中问 Sisowath Kossamak 的岳父，I 把答案从 King Sisowath Monivong 改成 King Norodom Suramarit，F1 从 0 升到 0.4，但标准答案是 Norodom Sutharot，两次都选错了家庭关系。这里不能说“修复了一个错误”。因此逐题汇总统一写分数提高／降低，不把每次 F1 提升都算成正确推理。官方指标不修改，具体语义错误另作解释。

21:18–21:27 检查发现，早期额外 `srun --overlap -c1` 步骤被 Slurm 限制在同一个 CPU 核上；分配中的其余 CPU 未被这些步骤使用。尝试设置进程亲和性无法越过步骤的 CPU 限制，未改变原进程。后续步骤统一使用 `--cpus-per-task=4 --cpu-bind=none`，仍共享原分配的四核和同一张 GPU，不增加分配卡数，也不改变算法、模型或解码。

三项尚处于早期的 LoCoMo QA 因此在新目录从 seed 42 重新开始，原部分预测全部保留，禁止挑较高分的一份：K 的 9B 正式重试根为 `source_policy_memory_cpu4_seed42_20260912`；M 的 9B 为 `single_source_paths_cpu4_seed42_20260912`；G 的 4B 为 `path_memory_cpu4_seed42_20260912`。它们复用原检索文件，没有重新选取 memory。原目录对应单元仅作为中止产物，不进入完整结果表。其余已完成或接近完成的单元未重跑。4B 数组尚未开始的五个元素也改为现有分配中的四核步骤，输出路径和评测设置不变。

另外，为避免主作业结束时 Slurm 杀掉仍运行的附加实验，只暂停了三个分配的外层 shell，模型子进程继续运行。每个分配有一个等待步骤，确认主结果和其他步骤结束后恢复 shell、释放分配。此操作不暂停推理、不修改实验产物；原始三小时 Slurm 时限仍有效。

两个原计划分配中的重复检查进程已暂停；独立步骤全部结束后，由等待步骤取消该冗余主进程并释放 GPU。取消状态不表示已完成的计划实验失败，完整预测与汇总均保留；也不据此把中途产生的重复检查结果计为完成。

## 与直接相关研究的界限

MemoryAgentBench 的事实更新规则是输入明确给出的“较大序号表示较新事实”，不是分析者新增的真值规则。[^5] 但把所有任务都改成“最后一条一定正确”会伤害历史查询，不能从这个 benchmark 的局部定义推出普遍记忆规则。

一项直接相关的后检索组装研究已经把语义证据识别和版本策略执行分开，并在每个分解的子问题上执行冲突处理。其报告明确区分完整流程改变与单独策略执行的贡献，也报告了 LongMemEval 上无优势的检查。[^6] 因此，“中间表示＋确定性执行”本身不是空白；后续必须比较实际操作和跨任务表现，不靠编译器词汇制造 novelty。

本轮优先检验可复用记忆、候选连接与读取时计算的收益。编译器和系统知识可帮助界定：哪些结构提前保存、哪些工作必须依赖当前问题、共享中间结果能否抵消新增成本。尚不存在自然语言语义等价证明，不能声称任意信息无损或形式化正确。

相关分类可按三个相互独立的角度展开：记忆保存成什么形式、承担事实/经验/工作记忆中的什么功能、在写入/更新/读取哪一阶段改进。最近的综述使用了这样的多维分类，而不是把 embedding、建图、streaming 混成互斥类别。[^7] 当前任务主要检验事实记忆读取；不据此宣称增强了长期工具使用或经验学习。

A-Mem 在写入时创建上下文描述、关键词和记忆链接，并更新已有记忆；这与本轮只在读取时添加笔记不同。[^8] Zep/Graphiti 已保存原始片段、实体和事实的关联及两种时间，并用文本、向量和图遍历检索；因此“保存来源＋时间＋建图”也不是未被研究的主张。其论文主要使用 LLM judge，我们不能把那个分数直接与这里的 token F1 拼表。[^9]

HippoRAG 2 自己的错误分析也区分了三元组过滤和图排序：有些相关概念在图中存在，经过过滤或最终排序后却没有进入需要的原文集合。[^10] 这与本地的“已抽出但未联合取回”案例相容，但其抽样比例不能移植成我们数据的失败占比。LoCoMo 的分词 F1 与类别特例来自官方实现；本轮保留它们，即使个别语义正确的不同表述会被低估。[^11]

新核对的最近邻进一步限制了 novelty 空间：KG²RAG 已将三元组与来源块绑定，在图上扩展，再组织原文；GeAR 已从起始事实展开多条路径并映回来源，也有查询重写和暂存相关事实的多步版本。[^14][^15] 因此，“三元组＋来源＋路径”本身不能算本项目独有。本轮和它们的具体差异是复用已完成的 agent memory 产物、在事实更新与对话任务中检查失效，并分开比较纯追加、路径展示、来源恢复及额外读出调用；这只是实验定位，还不是充分的新算法贡献。

## 最终停止时的证据边界

2026-09-12 02:55 UTC 核查，第一轮 150 个计划单元已完成 149 个，仅 L 的紧凑搜索 LoCoMo 最终 QA 未完成；其 1,986 题的搜索已全部完成。原 QA 超时，后继 QA 又按用户要求取消，该单元仍未完整完成。中断路径见第二轮记录，不把部分输出当作另一个完整方法，不继续自动补跑。

B 检查版 LoCoMo 已完整完成，F1 为 64.7512%，原合并为 59.4094%；类别 5 为 92.3767% 对 69.0583%，整体提升主要来自无答案题的拒答改善。B 检查版 2Wiki 为 52.8594%，没有相同幅度收益。D 两次搜索的 2Wiki 为 63.9068%、LoCoMo 为 59.3106%；L 紧凑搜索的 2Wiki 为 62.8128%。搜索预算、输入和额外调用均需单独报告，不能当作纯 memory 构建收益。

J 路径加原文的 9B LoCoMo 为 59.0984%，低于原合并的 59.4094%；其 4B 2Wiki 为 58.1478%。M 单套 HippoRAG 记忆路径版的 LoCoMo 为 50.9103%，不能用它在 2Wiki 的较好性价比概括全部任务。所有数值均来自完整 summary；运行中的部分题目不报告最终成绩。不同分支不能按 benchmark 名称路由取优。
