# 先分析，再定机制

比较同一Generator在不同生成流程中的产物，不先换更强模型，也不再做ensemble。

对齐：原文→初次抽取→整理后memory→检索→QA。区分遗漏、误写、整理损失、已存未取出、回答失败及适配问题。个案不冒充总体错误率。

已知例子：Mem0历史日期被运行日期错误锚定，属于适配问题；LightMem整理删除过有效陈述；另有记忆保留“昨天”却被QA读错；HippoRAG存有出生日期但没取回。不能统称Generator弱。

待验证假设：解释上下文与有损压缩是否应分开？若证据支持，尝试先生成忠实、可独立理解的记录，再组织和去重，减少反复自由改写。图只是候选，compiler暂不作为主线。

下一项实验只改一个有证据支持的生成操作，固定输入、模型、检索与QA协议，评测全部既定任务并记录token和时间。构建不读评测问题或答案；若主要错误不在memory生产，就放弃该假设。
